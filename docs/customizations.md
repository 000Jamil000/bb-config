# Настройка и восстановление

## Classic / Custom в боковом меню

Machine Tabs (`plugins/machine-tabs/`) добавляет текстовые кнопки
`Classic | Custom` рядом с New thread. Classic выбирает штатный провайдер
`thread-list/thread-list` установленной версии BB; Custom возвращает
`machine-tabs/machine-tabs`. Поэтому обновления штатного списка доступны
без копирования старого интерфейса. Переключатель остаётся в обоих режимах,
а выбор синхронизируется между окнами. Настройки Machine Tabs сохраняются.
Штатные предпочтения группировки и другие плагины остаются активными:
Classic переключает только провайдер списка тредов.

Восстановление на сервере BB: `bb plugin build plugins/machine-tabs`, затем
`bb plugin reload machine-tabs` для уже установленного плагина либо
`python3 scripts/restore.py --plugins --apply` с приватным снимком.
Выбранный провайдер сохраняется в `.local/config/ui.json`
и применяется `restore.py`. Вручную: `bb settings ui set
sidebar.threadListProvider '"thread-list/thread-list"'` или
`bb settings ui set sidebar.threadListProvider '"machine-tabs/machine-tabs"'`.
Кнопки привязаны к штатному заголовку Navigation; если его разметка изменится,
выбор остаётся доступен в Settings → Appearance → Sidebar и через CLI.

## Индикаторы usage

Для общего обзора расхода подключённых машин используется `Usage` (`usage`),
для статистики тредов и детализации по сообщениям — `Tokenomics` (`tokenomics`),
для лимитов аккаунта треда и общего обзора — собственный `Thread Account Usage`
(`plugins/thread-account-usage/`). Usage и Tokenomics остаются установленными
из каталога `bb-community`, чтобы сохранять штатные обновления.
Usage Tracker также сохранён из каталога, но отключён как дублирующий индикатор.
Исходники сторонних плагинов здесь не копируются.

В Usage Tracker штатная настройка `compactLimit` установлена в `Five-hour`:
`bb plugin config usage-tracker set compactLimit Five-hour`. Она сохраняется
в приватном снимке. Это меняет выбранное окно компактного индикатора и обзора,
но общий процент остаётся средним между аккаунтами; если пятичасового окна нет,
плагин использует доступное недельное. `+N` рядом означает число доступных
сбросов лимитов, а не дополнительные аккаунты. Дополнительные окна, включая
Fable, видны при открытии деталей конкретного аккаунта.

Восстановление: `bb plugin install usage@bb-community --yes`,
`bb plugin install tokenomics@bb-community --yes` и
`bb plugin install usage-tracker@bb-community --yes`, либо общий
`python3 scripts/restore.py --plugins --apply` с приватным снимком.
Прежние `bb--provider-usage`, `limits` и `usage-tracker` отключены штатной командой
`bb plugin disable <id>`, их настройки сохранены. Вернуть индикатор можно
командой `bb plugin enable <id>`. Плагин `ai-usage` не устанавливается.

Usage собирает историю с доступных подключённых машин; первый сбор может
занять время. Tokenomics читает доступные события истории BB и продолжает
учёт новых событий после установки.
Авторизации CLI и нестандартные пути профилей проверяются отдельно на каждой
машине; снимок настроек не содержит авторизации или историю использования.

### Thread Account Usage

В заголовке треда слева от существующего графика Tokenomics: логотип агента,
аккаунт CLI, сервер и единый значок с двумя вложенными кольцами. Рядом указаны
два наиболее исчерпанных применимых окна и время сброса каждого.
График Tokenomics подписан «Тред / 24ч»: он описывает расход этой беседы,
а кольца — общие лимиты аккаунта.
Плагин поддерживает несколько одновременно открытых тредов через SDK split
layout. Кнопки терминала остаются после блока usage. Кружок контекста BB
не меняется.

Внизу сайдбара — два кольца, подписанные средние проценты 5ч и недели,
и ручное обновление. Недельная строка приглушена. `+N` расположен маленькой
меткой у логотипа/нижнего угла значка, без слова «сброс» и фона.
Точка привязана к нижнему значку и означает подтверждённое исчерпание общего
лимита 5ч/недели; число аккаунтов показано в заголовке карточки. Исчерпанная
модель и устаревшие данные в этот счётчик не входят. Тексты увеличены и выровнены.
В заголовке логотип встроен в угол кольца, аккаунт и машина собраны в одну
компактную строку. Группы времени разделены узким неразрывным пробелом.
Кнопка обновления сохраняет размер и вращается при запросе;
данные остаются видимыми. Взаимодействие закрепляет карточку, её состояние не
зависит от перестройки DOM заголовка.
Карточка показывает компактные строки с логотипами, аккаунтами и названиями
машин; горизонтальные полосы 5ч / неделя / Fable имеют подписи, процент и
время сброса справа. Кнопка `›` раскрывает полные данные аккаунта и до шести
последних тредов этого агента на указанных машинах, без утверждения об их
исторической привязке к аккаунту.
Точная дата — по наведению. Переключатели выделяют одно окно; отсутствующее
окно не заменяется другим и не отображается как 0%.

На телефоне (до 767px) отдельный баннер лимитов над вводом убран. Короткая
кнопка с логотипом, кольцами и главным процентом встроена в существующую
горизонтально прокручиваемую нижнюю строку треда (`data-follow-up-composer-footer`).
Нажатие открывает подробности нижней карточкой с учётом клавиатуры и safe-area.
В боковом меню средние 5ч и недели остаются двумя выровненными строками;
исправлено слипание подписей на телефоне. Десктопные стили и размещение
сохранены. При изменении DOM-маркера BB нужно перепроверить размещение. На мобильном экране pointerdown/mousedown по кнопкам нижней строки сохраняет фокус редактора до click, чтобы blur не сворачивал панель раньше открытия меню. Обработчик не останавливает распространение событий и не перехватывает touchmove; десктоп не затрагивается.
`+N` внизу и у аккаунта обозначает известные доступные сбросы. Read-only
host worker читает количество сбросов Codex через существующий CLI,
сопоставляет email и не расходует кредиты. Для Claude количество пока
неизвестно и не заменяется нулём.

Запросы к штатному SDK BB выполняются раз в 2 минуты, по фокусу и вручную,
таймер — каждые 30 секунд. Авторизация и маршрутизация не меняются. Один
логин на нескольких машинах объединяется без суммирования процентов.
Аккаунт треда определяется как текущий вход CLI на его машине с проверкой
метаданных запуска. Это не подтверждение авторизации уже запущенного процесса.
Отдельный профиль/маршрут, включённый пул или отсутствие метаданных дают
явный статус «Аккаунт не подтверждён» вместо чужих лимитов.

Настройка `hideGlobalTokenomics` скрывает верхний левый индикатор Tokenomics
адресным стилем нашего плагина; файлы готового плагина не меняются.
Можно вернуть через `bb plugin config thread-account-usage set
hideGlobalTokenomics false`. После отключения нашего плагина скрытие и
добавленные DOM-элементы удаляются.

Восстановление на сервере BB: `npm ci --prefix plugins/thread-account-usage`,
`bb plugin build plugins/thread-account-usage`, затем
`bb plugin install ./plugins/thread-account-usage --yes` и
`bb plugin disable usage-tracker`. Снимок поддерживает общий restore.
Исходники, зависимости и ограничения DOM-якорей BB описаны в
`plugins/thread-account-usage/README.md`. Проверки: TypeScript и
`node --test plugins/thread-account-usage/logic.test.ts`.
Для отката отключите `thread-account-usage` и включите `usage-tracker`.

### Совместимость Tokenomics 0.2.2

В ответе `usage_limits` неизвестная оценка `sizeTokens` возвращалась как
`undefined`, что текущий BB отклоняет с `non_json_result`. Исправление
`plugins/tokenomics-compat/server.patch` преобразует её в допустимый по схеме
`null`. Плагин остаётся установленным из каталога; исправляется только его
серверный ответ, интерфейс и учёт токенов не меняются.

На машине сервера BB выполните `python3 scripts/apply_tokenomics_compat.py`
для проверки и `python3 scripts/apply_tokenomics_compat.py --apply` для
применения, сборки и перезагрузки через CLI. Скрипт проверяет версию и
контрольные суммы исходника, не читает базы и не меняет авторизации.
После восстановления или обновления плагина исправление нужно проверить
заново: обновление из каталога заменяет исправленные файлы. При неизвестной
версии или контрольной сумме скрипт останавливается для проверки upstream.
Проверка результата: `bb plugin rpc call tokenomics usage_limits --json`
должна завершиться без ошибки JSON; статистика тредов доступна через
`bb tokenomics threads --limit 3 --json`.

## Установка

План показывает `python3 scripts/restore.py --plugins`. Для применения запустите
его с `--apply` на машине сервера BB. Локальные плагины устанавливаются из
`plugins/<id>/`; сторонние — из сохранённых источников каталога.

`restore.py` читает `config/` и `.local/config/`. Локальные значения заменяют
одноимённые публичные ключи; вложенные словари и списки заменяются целиком.
Личные файлы плагинов обнаруживаются даже при отсутствии публичного файла.
Новый checkout без `.local/` получает только общие настройки.

## Сохранение

После изменения BB проверьте источник через `bb plugin list --json`, затем:

```sh
python3 scripts/snapshot.py --settings-only
python3 scripts/snapshot.py --check
python3 scripts/privacy_check.py
```

Снимок содержит список плагинов и настройки без секретных полей схемы.
Он сохраняется только в `.local/config/`. Полный режим без `--settings-only`
копирует исходники установленных локальных плагинов, поэтому требует чистого
каталога `plugins/` и отдельной проверки кода на личные значения.
Публичные настройки редактируются вручную после обезличивания.

`setup_tracking.py --apply` добавляет общее напоминание и включает Git-хук.
Хук проверяет актуальность приватного снимка и содержимое Git index.
Проверка истории перед публикацией: `python3 scripts/privacy_check.py --history`.
Коммиты, push и открытие доступа выполняются по отдельному поручению.

## Ручные шаги

Пароли и авторизации вводятся отдельно. Сетевой доступ Connect, маршруты прокси,
ACP-агенты и чувствительные состояния сетевых плагинов автоматически не меняются.
Идентификаторы машин после новой установки сопоставляются заново.
Сложные горячие клавиши, пользовательский CSS, выбранные вкладки и лимиты машин
проверяются вручную. Маршруты и аккаунты Claude не меняются при сборе снимка.

При установке Web BB Button задайте «Публичный адрес BB» (`webUrl`) в штатных
настройках плагина. Если на сервере уже задан `BB_APP_URL`, он может использоваться
при пустой настройке. Без корректного адреса плагин показывает статус «Требуется
настройка» и инструкцию; сохранение настроек повторяет его загрузку.
Переходов на главную по умолчанию нет. Личный URL хранится в BB и приватном
снимке `.local/config/plugins/web-bb-button.json`. Серверное перенаправление
`/api/v1/plugins/web-bb-button/http/open` открывает сохранённый адрес.
После правки плагина выполните `bb plugin build <путь>` и `bb plugin reload <id>`.

Личные адреса доставки бэкапа задаются в `.local/config/backup-delivery.json`:

```json
{
  "destinationHost": "host_example",
  "destinationDir": "/path/to/private/backups",
  "compatHost": "host_example"
}
```

`server_backup.py` также принимает `--destination-host`, `--destination-dir`,
`--recipient`. `apply_inbox_compat.py` принимает `--host` и без `--apply` только
проверяет известные контрольные суммы. При изменении upstream требуется новый
просмотр совместимости. Скрипты не читают и не меняют базу BB напрямую.

## Публикация изменений

Проверяйте diff и запускайте `scripts/privacy_check.py` для текущих файлов и с
`--history` для истории. Личные документы и конфигурацию храните в `.local/`.
При очистке уже существовавшей истории сохраните приватный Git bundle и свои
незакоммиченные файлы. Старые checkout нельзя сливать обратно в очищенную историю:
клонируйте репозиторий заново, затем перенесите собственные незавершённые правки.

Данные в `.local/` отсутствуют в GitHub. Шифрованное резервное копирование и
восстановление описаны в [server-backups.md](server-backups.md).

## Project Open

`plugins/project-open/` добавляет иконки папки и терминала в строках тредов и в
заголовке треда, без замены списка и меню BB. В заголовке они видны постоянно;
в боковом меню появляются при наведении/фокусе только на десктопе. На
сенсорных устройствах дополнительные кнопки в строках вообще не монтируются,
поэтому скрытые элементы не перехватывают нажатия на тред. В строках бокового меню кнопки накладываются на правый
край названия без резерва места (кнопки стоят в штатном ряду действий с одинаковым шагом 20 px); в заголовке треда ширина сохраняется, чтобы
штатные кнопки не сдвигались.
Обе кнопки показывают тёмный тултип с задержкой 100 мс: действие, имя машины
и полный путь окружения. Машина и путь показаны отдельными строками с
иконками ноутбука и папки. Данные сразу берутся из живого списка BB и уточняются
через SDK треда, окружения и машины при открытии подсказки.
В строках с дочерним тредом из другого проекта сохраняется штатный значок
перехода в проект: при наведении он располагается перед всем рядом действий
без наложения на кнопку папки. Такое смещение применяется только к мыши;
на сенсорном экране сохраняется штатное положение стрелки и значка проекта,
а область нажатия стрелки расширена до 36×36 px.
Новые иконки стоят перед штатным Open. Терминал запускается штатным
New tab → Start terminal в нужной папке и на нужной машине.

На macOS папка открывается напрямую в Finder через локальный обработчик
`BB Project Folder.app`. Он использует уже установленный rclone и существующий
SSH-профиль; удалённый корень подключается нативным WebDAV-диском через loopback.
NFS и Cyberduck в рабочем сценарии не используются. Локальная папка открывается
без сетевого подключения. Каждый заголовок получает ID своего треда из
контекста композера, включая split-панели. В боковом меню используется ID
конкретного треда; машина и путь берутся из его окружения при нажатии, включая
worktree. У групп проектов кнопок нет: треды проекта могут быть на разных
машинах. Зависимость от маркеров Machine Tabs для выбора папки убрана.

Восстановление BB-плагина: `python3 scripts/restore.py --plugins --apply`.
Для установки клиентского обработчика скопировать каталог `macos/` из
плагина на Mac и выполнить `python3 macos/install.py --config <private-config>`.
Личный конфиг содержит только путь rclone, ID машин, допустимые корни и имена
существующих SSH-профилей. Ключи и авторизации не копируются. После проверки
включить `finderHelper` в настройках Project Open. Разрешение application-link
схемы выдаётся штатным интерфейсом BB на клиенте. Обработчик специфичен для
macOS. На iPhone/iPad/Android кнопка в заголовке открывает штатный поиск
файлов BB в контексте треда через New tab; Mac-ссылка на телефоне не вызывается.
На других десктопных ОС остаётся штатный Open BB.

Исходники и подробности — `plugins/project-open/README.md`. Проверки:
`npm test`, `npm run typecheck` и
`python3 -m unittest discover -s macos -p 'test_*.py'` в каталоге плагина.
Системный обработчик должен пройти реальное открытие локальной и удалённой
папок в Finder, повторное нажатие и переподключение диска; одного открытия
меню или успешного mount/stat недостаточно. Личные значения восстановления
хранятся в `.local/docs/folder-helper-mac.json` и `.local/docs/project-open.md`.
Журналы, статусы запросов и файловый кэш в Git и снимок настроек не включаются.

## Автоматизации и наблюдение за очередями

Исходники проверок сохранены в `scripts/thread_watchdog.py` и
`scripts/thread_queue_monitor.py`; резервное копирование — в
`scripts/server_backup.py`. Установленные автоматизации содержат отдельные
копии скриптов. Правка checkout сама по себе не меняет работающую проверку.

`scripts/automation_config.py --snapshot --project <project-id>` сохраняет
известные расписания этих скриптов в игнорируемый файл
`.local/config/automations.json`. Флаг `--project` можно повторять. В снимок
входят включённость, cron, часовой пояс, таймаут, рабочий каталог и только
разрешённые переменные окружения. Переписки, ключи, базы, содержимое бэкапов,
история запусков и наблюдений не сохраняются в репозитории. Приватный манифест
включается в зашифрованный архив `.local/config/`, описанный в
[server-backups.md](server-backups.md).

Восстановление: сначала `python3 scripts/automation_config.py` показывает
план без изменений; `python3 scripts/automation_config.py --apply` обновляет
существующие расписания или создаёт отсутствующие из исходников checkout.
Перед применением на новой установке сопоставьте project/thread ID, пути
и параметры доставки в приватном манифесте. Для другого хоста скрипты должны
быть доступны на хосте вызывающего CLI. Повторное применение сопоставляет
задания по ID, затем по точному имени. Неоднозначные имена останавливают импорт.

Проверки запускаются раз в минуту и не требуют модели. Общий монитор только
наблюдает очередь всех доступных проектов и посылает штатное BB-уведомление:
`turn-starting` дольше 5 минут, `thread-busy` дольше 15 минут либо исчерпанные
попытки доставки. Долгое ожидание не объявляется доказанным зависанием.
Запланированные сообщения, вопросы, ожидание плагинов и недоступные машины
не считаются таким сбоем. Уведомления ограничены одним на тред за 30 минут.
Обезличенные технические наблюдения (ID, время, статус, причина очереди)
хранятся только в служебной директории, с ротацией двух файлов до примерно
2 МБ каждый; состояния удаляются через 7 дней без наблюдений.

Отдельная защита одного выбранного треда повторяет доставку уже сохранённого
сообщения и возобновляет только явно диагностированный сбой запуска
`provider_turn_start_deadline` / `provider_turn_start_timeout`. Она не
останавливает работающий ход, не очищает контекст, не отвечает на вопросы,
не подтверждает разрешения и не возобновляет ручную остановку. Не более трёх
попыток до нового сообщения пользователя, с интервалом не менее 3 минут.
Новый запрос автоматически возвращает наблюдение без ручного включения.
Состояния и счётчики не содержат текста сообщений. Если проблема —
рассинхронизация BB при продолжающейся работе провайдера, принудительного
перезапуска нет: собираем данные для исправления причины.

## Дополнительная Linux-машина и прямой маршрут Codex

Машина подключается к существующему BB исходящим соединением через Connect;
SSH-переход используется только для установки и обслуживания и не определяет
исходящий маршрут Codex. Установить поддерживаемый Node.js, зарегистрировать
машину через штатный manual installer и проверить автозапуск systemd.
Приватные команды регистрации, токены и файлы авторизации не сохранять.

Для прямого выхода Codex выполнить `bb proxy-manager prepare <machine> direct`,
`bb proxy-manager apply <machine> direct`, затем `bb proxy-manager check <machine> direct`.
Проверка без токена подтверждает сеть; вход в аккаунт выполняется отдельно на
целевой машине. Маршруты и идентификаторы сохранены только в приватном снимке.
На VPS с небольшим объёмом RAM проверить swap перед установкой CLI и запуском агентов.

## Имена фоновых служб macOS

`scripts/macos_named_services.py` оформляет описательные запускатели для
существующих LaunchAgents BB/McpGo в Login Items. Для каждого задания
используется понятное имя функции: Mac Connection, Terminal, Quick Commands,
Browser, Browser Proxy, Tunnel, Messages, Auto-send, Dashboard.
Это маленькие нативные программы из `scripts/macos_service_launcher.c`,
которые выполняют исходный Node с теми же аргументами и окружением.
Сам Node, реализации служб и разрешения Privacy не заменяются.

План: `python3 scripts/macos_named_services.py`. Применение на Mac:
`python3 scripts/macos_named_services.py --apply`. Скрипт сначала собирает
и проверяет все запускатели, затем меняет только исполняемый путь и
ассоциацию приложения в существующих пользовательских LaunchAgents.
По умолчанию службы не перезапускаются; отдельный `--restart` применяется
только по необходимости. Неактивные задания остаются неактивными.

Состояние отката хранится на Mac в
`~/Library/Application Support/BB Named Services/state.json`: только исходные
пути и ассоциации, без аргументов служб, окружения и авторизаций. Откат:
`python3 scripts/macos_named_services.py --rollback --apply`.
Копия состояния и личные детали — `.local/docs/mac-login-items-state.json`.
После обновления менеджера служб, если он пересоздаст LaunchAgents, повторить
план/применение: запускатель будет использовать актуальный оригинальный Node.
Не применять resetbtm, не править базу TCC и не переносить разрешения для
косметического изменения Login Items. Подпись локальная; Developer ID
производителя эти личные запускатели не присваивают.

## Компактный экран подключений

В `proxy-manager` сохранено компактное дерево «машина → установленные агенты».
Каждая машина оформлена отдельным блоком с выделенным заголовком;
строки агентов имеют общий контур для названия, настройки и статуса и
соединены с машиной ветками. Ветки раскрыты по умолчанию и сворачиваются
нажатием на заголовок; показаны число агентов и связь машины. Неустановленные CLI скрываются по
признаку установки, а установленный, но недоступный агент остаётся видимым
с пояснением. Выбор прокси находится в строке Codex; у остальных агентов
отображается «Прокси не управляется»: плагин пока не меняет их маршрут.
Уменьшены отступы; шапка с кнопкой «Назад»
остаётся видимой при прокрутке.
Открытие из индикатора и возврат в тред выполняются штатной навигацией
SDK BB без перезагрузки документа. Адрес исходного экрана и машина
сохраняются в памяти вкладки; обычная ссылка остаётся для открытия
в новой вкладке. Старые ссылки с `returnTo` также возвращают в тред через SDK.
При открытии без исходного адреса используется история браузера,
а в новой вкладке — штатный экран создания треда.

Работает в веб-интерфейсе установленного плагина. Восстановление:
`bb plugin build plugins/proxy-manager`, затем установка локального пути
`bb plugin install ./plugins/proxy-manager` или `bb plugin reload proxy-manager`,
если этот путь уже установлен. Исходники: `app.tsx` и `proxy-ui.css`.

Данные экрана подключений сохраняются в памяти вкладки и сразу отображаются
при повторном открытии; актуальные машины, привязки и статусы загружаются
в фоне. Обнаружение CLI кэшируется на сервере на 60 секунд, одновременные
проверки одной машины объединяются. Кнопка обновления обходит кэш; перед
сменой маршрута наличие CLI проверяется принудительно. Кэш не записывается
в настройки и не требует отдельного шага восстановления.

## Группы по пять и поиск тредов

В Machine Tabs каждый список начинает с пяти элементов. Компактные текстовые
кнопки со стрелками «Показать ещё» (+5) и «Свернуть» (до 5) расположены
в одной строке со счётчиком и проявляются при наведении на блок или фокусе
внутри него. На сенсорном экране кнопки видны постоянно. Это относится
к Last 5, проектам, машинам, дням и вложенным спискам: ограничивается вход
штатного виртуализатора, поэтому скрытые строки не остаются целями навигации.
Раскрытие хранится в состоянии компонента до его размонтирования.
Счётчик пагинации не переносится и не сжимается; на сенсорных экранах
промежутки уменьшены, чтобы обе кнопки и `10 / 14` помещались в строку.
Last 5 сохраняет связи родитель/потомок и передаёт дочерние треды штатному
списку BB, поэтому стандартные стрелки, вложенность и индикаторы работают
и в этом блоке. Сброс parentThreadId и фильтр только корневых тредов убраны.

Поле «Поиск тредов» проверяет названия всех активных тредов, включая
не раскрытые строки и группы, а также названия проектов, машин и дней.
All ищет по всем машинам; конкретная вкладка ограничивает результаты своей
машиной. Кнопка настроек появляется при наведении/фокусе; переключатели
«Включая архив» и «По тексту сообщений» выключены по умолчанию и действуют
до перезагрузки страницы. Нового постоянного вида настройки нет.
Названия активных тредов проверяются сразу. Архивные названия загружаются
страницами по 100 в фоне, кэшируются на минуту в памяти вкладки; поиск
по сообщениям использует штатный индекс BB. Задержка 250 мс и отмена
предыдущего запроса предотвращают запрос на каждое нажатие клавиши и
появление устаревших результатов. Дополнительные совпадения показываются
отдельным компактным блоком, также по пять.

Ограничение штатного API: поиск по сообщениям возвращает максимум 50
тредов на категорию (активные/архивные), затем применяется выбранная машина.
При превышении лимита интерфейс предлагает уточнить запрос. Архивный поиск
по названиям проходит все страницы метаданных и этим лимитом не ограничен.
Тексты сообщений, запросы и результаты на диск не записываются.

Восстановление: `bb plugin build plugins/machine-tabs`, затем
`bb plugin install ./plugins/machine-tabs`; если путь уже установлен —
`bb plugin reload machine-tabs`. Исходники дополнения: `app.tsx`,
`lib/group-paging.tsx` и `lib/thread-search.tsx`. После обновления BB проверить
пагинацию: адаптер использует семантические props штатного JSX-рендерера
(`itemKeys`, `renderItem`, навигационные функции) и отдельный вход pinned;
минифицированные имена функций и исходник штатного плагина не меняются.

## HOME у системной службы BB

Если системная служба BB запущена без `User=`, systemd может не задать `HOME`.
Его отсутствие наследуют терминалы и агенты; CLI могут ошибочно искать
учётные данные относительно рабочего каталога. Авторизация хранится только
в штатном пользовательском хранилище, не в checkout проекта.

`scripts/bb_service_home.py <bb-unit.service>` проверяет пользователя службы
и его домашний каталог. `--apply` устанавливает отдельный systemd drop-in
`90-bb-home.conf` с правильным `HOME` и выполняет `daemon-reload`, не перезапуская
службу. После перезапуска `--verify` проверяет окружение работающего демона.
Для восстановления выполнить тот же скрипт с `--apply` от администратора.
Перед прерыванием работы включить штатное продолжение тредов после рестарта:
`bb settings experiment resumeThreadsAfterRestart true`. Эта настройка входит
в приватный снимок; ранее остановленные пользователем и ожидающие разрешения
треды автоматический механизм не возобновляет.

## Прокси в нижней строке поля ввода

Индикатор прокси перенесён из баннера над полем ввода в нижнюю строку:
проект → ветка → машина → прокси → новая сессия. Индикатор целиком открывает
экран подключений через SDK-навигацию. Штатные элементы строки и их действия
сохранены; `composer-footer.ts` добавляет только контейнер для React portal
и атрибуты порядка через content script, убирая их при выгрузке. Каждая
форма ввода привязана к своему контейнеру. Нижняя строка не переносится,
поскольку штатный контейнер BB имеет фиксированную высоту. На телефоне
«Пуш» находится возле строки изменений (если её нет — возле ветки), поэтому
внизу помещаются ветка, прокси с текстом и штатные режим/контекст. Подписи
сохранены, область нажатия имеет высоту 44 px. Pointerdown на наших кнопках
сохраняет фокус композера до обработки клика: поле не сворачивается раньше
перехода в настройки прокси.
Если структура строки в новой версии BB не распознана, индикатор остаётся
среди действий поля ввода. SDK-декларации обновлены до версии работающего BB.

## Кнопка «Пуш»

`plugins/push-button/` добавляет кнопку рядом с веткой внизу существующего
треда. Нажатие отправляет обычное сообщение `пуш` через SDK BB в этот тред.
Если агент занят, используется штатная очередь (`queue-if-active`). Кнопка
не запускает Git и не меняет черновик, модель или разрешения. Проверку, коммит
и отправку выполняет агент по полученному поручению. Есть защита от повторного
нажатия во время отправки; после ошибки можно повторить.
Кнопка приглушена и отключена, если нет изменений/неотправленных коммитов,
либо статус ещё загружается или машина недоступна. Read-only host entry читает
Git в окружении треда: изменения, ahead относительно фактической tracking-ветки
и первую публикацию локальной ветки. Обновление раз в 5 секунд, только пока
интерфейс подписан на статус; fetch не выполняется.

Плагин отдельный, не заменяет штатные элементы ветки и изменений. Для
восстановления: `python3 scripts/restore.py --plugins --apply`; при ручной
установке — npm ci, bb plugin build и установка из каталога плагина.
Проверки: `npm run typecheck`, `npm test` в каталоге плагина.

На телефоне над композером также показано имя машины с иконкой. Оно
получено из окружения именно этого треда через SDK, включая состояние
недоступного Git, а не из выбранной вкладки машин.

## Menubar Status: статусы агентов в строке меню macOS

Плагин `menubar-status` (`plugins/menubar-status`, только серверная часть) собирает
короткую сводку по тредам: сколько ждут ответа, сколько работают, есть ли новые
ответы и ошибки, плюс последние агенты с проектом, машиной и одной строкой
последнего ответа. Сводку он записывает штатным `bb.sdk.files` в JSON-файл на
выбранной машине: при событиях тредов (с задержкой около секунды) и не реже раза
в минуту. Зачем: значок bb в Dock показывает только число или точку, а всплывающее
окно при наведении на значок Dock в macOS сделать нельзя.

На машине с виджетом работает SwiftBar со скриптом
`plugins/menubar-status/macos/bb-agents.5s.py`. Скрипт только читает локальный файл:
без сети и без учётных данных, поэтому обновление мгновенное. Если файл не
обновлялся три минуты (сервер недоступен, машина спала), виджет показывает, что
данные устарели. Клик по строке открывает приложение bb, клик с Option — тред в
браузере по публичному адресу.

Настройки плагина (`bb plugin config menubar-status set <ключ> <значение>`):
`hostId` — машина с виджетом, `filePath` — абсолютный путь файла на ней,
`webUrl` — публичный адрес BB для ссылок, `maxItems` — число строк. Значения
личные: они хранятся в BB и в приватном снимке `.local/config/plugins/menubar-status.json`.
Без `hostId` и `filePath` плагин показывает статус «Требуется настройка».

Восстановление: `python3 scripts/restore.py --plugins --apply`, затем задать
настройки. Ручной шаг на Mac: `brew install --cask swiftbar`, указать SwiftBar
папку плагинов и положить в неё `bb-agents.5s.py` с правом на исполнение; путь к
файлу по умолчанию `~/Library/Application Support/bb-menubar/status.json`,
другой задаётся переменной `BB_MENUBAR_STATUS`.

Проверки: `bb menubar-status show` печатает сводку, `bb menubar-status sync`
записывает файл сразу; `node --experimental-strip-types --test feed.test.ts` в
каталоге плагина.

В machine-tabs подсказка при наведении на значок проекта в строке треда теперь
содержит и машину («проект · машина»): машину видно при любой группировке без
новых элементов в строке.

## Voice Mode: разговор с агентом через подписку

Из каталога BB установлены сторонние плагины `voice-mode` (Voice Mode) и
`codex-realtime` (ChatGPT Realtime Connection). Они остаются управляемыми
Git-установками для получения обновлений; локальные копии исходников не нужны.
Voice Mode работает с агентом текущего треда, включая Codex и Claude Code.
Микрофон и воспроизведение работают в клиенте BB, соединение с OpenAI — на
машине сервера BB. Мобильное устройство требует отдельной проверки микрофона,
воспроизведения и перебиваний при открытом экране.

Настройка `connection=plugin` запрещает переход на платный API-ключ при ошибке.
API-ключ не задан. Голос — `shimmer`, текст передаётся дословно
(`messageText=verbatim`), `prefixMessages=true` помечает голосовые сообщения.
Начало разговора: открыть тред с пустым полем ввода и свободным агентом,
нажать волну вместо кнопки отправки либо выполнить команду «Start or end voice
chat» (по умолчанию Ctrl+Shift+V). При первом включении разрешить микрофон;
попросить отвечать по-русски. Mute отключает микрофон, × завершает разговор.
Подтверждения опасных действий и разрешения агента остаются в интерфейсе BB.

`codex-realtime` читает существующий вход Codex на сервере и передаёт токен
только разрешённому плагину `voice-mode`. Это недокументированный способ
доступа к Realtime через подписку: он расходует её лимиты, может перестать
работать и не является бесплатным безлимитным API. Во время разговора OpenAI
получает аудио и часть контекста треда. Отдельный речевой движок TTS не
устанавливается: речь создаёт OpenAI Realtime. Авторизация не входит в снимок.

Восстановление: `python3 scripts/restore.py --plugins --apply` устанавливает
плагины и применяет несекретные настройки из приватного снимка. На машине
сервера должен отдельно существовать действующий вход Codex через ChatGPT;
не копировать `auth.json` в репозиторий. При истёкшем входе пользоваться
штатным Codex, не обновлять токен средствами второго плагина.
После восстановления проверить `bb plugin list --json`,
`bb plugin config voice-mode` и запуск на нужном устройстве. До нажатия
кнопки начала разговора микрофон не захватывается.

Серверная проверка: штатный `codex-realtime/scripts/live-check.ts` с короткой
синтетической русской фразой подтвердил подключение по подписке,
распознавание и получение русскоязычного голосового ответа без ошибок.
Тест не проверяет микрофон клиента, перебивания, отправку реальной задачи
агенту или мобильное воспроизведение: их нужно проверить в живом разговоре.

### Правки диалога и мобильного микрофона

Для Voice Mode 0.1.15 сохранён воспроизводимый патч в `plugins/voice-mode/`.
Установка остаётся из каталога; это не отдельный форк плагина. После готовности
микрофона каждый новый сеанс произносит случайное короткое приветствие из
30 спокойных и шуточных вариантов. Предыдущая фраза исключается, пока плагин
загружен; перезагрузка сбрасывает память предыдущего выбора. Ответы
настроены на русский язык и первое лицо, без упоминания отдельного агента.
Приветствие не вызывает инструменты и не читает контекст проекта.

Исправлено скрытие обычного микрофона на телефоне: штатная кнопка записи
может находиться внутри группы отправки, которую исходный плагин скрывал
целиком. До и после голосового сеанса она остаётся доступна рядом с Voice Mode.
Во время сеанса микрофоном управляет голосовая панель; для обычного сообщения
сначала завершить разговор.

Для снижения ложных перебиваний убрана локальная остановка по одной громкости.
Используется серверный детектор речи: `vadThreshold=0.7`,
`silenceDurationMs=900`, `noiseReduction=far_field`, язык распознавания `ru`.
Перебивания сохраняются по событию начала речи; теперь они зависят от задержки
сервера. Тихая речь может потребовать снижения порога. Для гарнитуры можно
выбрать `near_field`. Отделение голоса пользователя от телевизора или чужой
речи не гарантируется.

Восстановление после обычного `restore.py --plugins --apply`: выполнить
`python3 plugins/voice-mode/apply.py --apply`, затем обновить и проверить снимок.
Основной restore пропускает три новых параметра, которых нет в исходном плагине;
скрипт патча применяет их из приватного снимка после сборки. Скрипт сохраняет
резервную копию исходников и сборки в игнорируемую `.local/plugin-patches/`,
откатывает их при ошибке и отказывается применять правку к незнакомой версии.
Обновления из каталога сопровождает `voice-mode-keeper`: совместимые правки
проверяются и применяются автоматически, несовместимые не накатываются.
Применение перезагружает плагин и завершает текущий голосовой разговор.

Проверки: 48 тестов upstream с регрессиями приветствия и настроек речи,
TypeScript, браузерная проверка разметки кнопок при ширине 390 px.
Проверка живого подключения через подписку приняла параметры шумоподавления и
вернула голосовое «Я готов. Что сделать?» без ошибок. Реальный микрофон телефона
и качество фильтрации бытового шума требуют проверки пользователем.
Для обновлённого патча также проверены 30 уникальных приветствий, исключение
предыдущего выбора, применение к исходной и предыдущей версии правки и
идемпотентность. Скрипт проверяет SHA-256 известных состояний каждого файла,
чтобы обновление самого патча не применяло старые изменения повторно.

В голосовых инструкциях, описаниях инструментов и служебных результатах убраны
формулировки о передаче задачи отдельному агенту. Короткие подтверждения,
статусы и итоги должны звучать от первого лица одного собеседника: «Сейчас
посмотрю», «Проверяю», «Нашёл». Реальные сведения о проектах и настройках
по-прежнему запрашиваются через инструменты; выдумывать результаты нельзя.
На прямые вопросы об архитектуре следует отвечать честно.
Тембр переключён с `marin` на `shimmer` для сравнения; Juniper из приложения
ChatGPT в поддерживаемом наборе голосов этого Realtime-подключения отсутствует,
точное соответствие не обещается. Манера речи задана как спокойная разговорная,
без дикторского пафоса. Голос меняется только в новом голосовом сеансе.

### Автоматическое сохранение правок при обновлении

Установлен собственный небольшой плагин `voice-mode-keeper` из
`plugins/voice-mode-keeper/`; сам Voice Mode остаётся установлен из каталога
и получает обычные обновления. Каждые 30 секунд сопровождение проверяет смену
версии или сборки и ждёт окончания штатного задания обновления BB.
Для совместимой ветки 0.1.x (не ниже 0.1.15) точные изменения проверяются
во временной копии: тесты upstream с регрессиями, TypeScript и сборка. Только
после этого заменяются исходники и сборка с сохранением резервной копии.
Ошибка активации вызывает откат; журнал позволяет восстановиться после
прерывания процесса. Параллельное обновление или изменение файлов не затирается.
Выключенный Voice Mode автоматически не включается.

Голос и остальные разрешённые несекретные предпочтения сохраняются отдельно
в состоянии сопровождения. Токены, авторизации, аудио и переписки не читаются
и не копируются. После успешной проверки обновляется приватный снимок.
При несовместимой версии остаётся исходный Voice Mode, в интерфейсе появляется
предупреждение; состояние доступно в настройках сопровождения и через
`bb plugin rpc call voice-mode-keeper status --json`. Для обычного совместимого
обновления ручное применение патча больше не требуется.

Восстановление: обычный `python3 scripts/restore.py --plugins --apply`
устанавливает сопровождение вместе с его закреплёнными зависимостями.
Соседняя папка `plugins/voice-mode/` должна оставаться доступной. На новой машине
один раз задать её штатный CLI:
`bb plugin config voice-mode-keeper set cliPath "$(command -v bb)"`.
Путь хранится только в приватных настройках. Это нужно потому, что серверный
процесс BB не обязан иметь CLI в PATH. Обработчик не меняет подключение
OpenAI, подписку, платёжные настройки или маршруты агентов.

Проверки: имитация совместимого обновления во временной копии с 48 тестами и
проверкой типов; 8 тестов отказа, отката, конкурентного обновления, отключения
и восстановления после прерывания; сборка и рабочее состояние сопровождения.

### Читаемая нижняя панель и голос из нового треда

В `proxy-manager/proxy-ui.css` для экранов до 640 px подписи нижней строки
не сжимаются до нескольких букв: строка прокручивается горизонтально и
сохраняет штатную высоту 32 px. Многострочная сетка убрана: футер BB резервирует
одну строку, поэтому увеличение её содержимого вызывало наложение на поле
ввода при открытой клавиатуре. Подписи 14 px; штатные обработчики и настройки
маршрутизации не меняются. При 1024 px остаётся исходная раскладка.
Правка хранится в исходниках собственного плагина и восстанавливается обычным
`restore.py --plugins --apply`.

Регрессионная страница `plugins/proxy-manager/tests/footer-layout.html` проверяет
футер вместе с полем ввода и зарезервированной высотой: отсутствие наложения,
выхода страницы за ширину, обрезанных подписей и доступность последнего пункта
прокруткой. Проверены ширины 320/390/430/1024 px и высоты 844/500/420 px.
Уменьшенная высота имитирует область над клавиатурой; настоящую клавиатуру iOS
такая проверка не воспроизводит.

В патч Voice Mode добавлена компактная кнопка с волной рядом со штатным
микрофоном в области `new-thread`, без отдельной широкой плашки.
По нажатию SDK создаёт обычный видимый тред с
выбранными проектом, окружением/машиной, провайдером, моделью и разрешениями.
Служебное первое сообщение просит лишь подтвердить готовность, без команд и
правок проекта; затем включается голос и открывается созданный тред.
Черновик с текстом не заменяется: сначала его нужно отправить или очистить.
Если пользователь ушёл с экрана во время создания, микрофон позже сам не
включается. Начало разговора использует обычные лимиты выбранного агента.

Проверки: 51 тест Voice Mode и TypeScript; сохранение выбранного окружения,
модели и режима разрешений, отказ при невыбранном проекте; проверка наложения
обновлённого патча на имитацию новой совместимой версии. Нажатие на настоящем
телефоне и системный запрос микрофона требуют проверки на устройстве.

В прокручиваемой строке отключено скрытие полных названий и принудительное
сжатие компактных контролов BB. Переопределения находятся в том же базовом
CSS-слое, что и важные правила хоста. Если штатного выбора машины нет, рядом
с маршрутом отображается её имя только для чтения. Касания маршрута не
отменяют стандартную горизонтальную прокрутку. Проверка использует собранный
CSS и правила скрытия хоста; дополнительно проверяются видимость названий и
компактное размещение кнопки Voice Mode, перенос при перерисовке и очистка.

### Одна подпись машины в нижнем статус-баре

В `proxy-manager` убрана добавочная подпись машины рядом с прокси. BB

Виджет в строке меню показывает по одной строке на агента: системный значок
состояния, название, проект серым и возраст справа; группы — «Ждут вас»,
«Ошибки», «Работают», «Новые ответы», «Недавние». Последний ответ виден в
подсказке при наведении и в подменю строки. SwiftBar добавлен в объекты входа
macOS, чтобы виджет появлялся после перезагрузки.

Панель по клику (вид как у Kordon): левый клик по значку `bb` в строке меню
открывает всплывающее окно с крупным текущим статусом («1 агент ждёт вас»),
главной кнопкой и карточками агентов по группам — значок агента, состояние,
проект, машина, две строки последнего ответа (при наведении шесть) и кнопка
«открыть тред в браузере». Правый клик открывает прежнее простое меню. Панель —
`macos/panel.html`, её отдаёт локальный помощник `macos/server.py`: слушает только
127.0.0.1:47615, отдаёт страницу и `status.json`, по клику открывает приложение bb
или адрес треда из сводки; каждый запрос требует токен из
`~/Library/Application Support/bb-menubar/token` (создаётся при установке, права 600,
в репозиторий не попадает). Если помощник не отвечает, левый клик тоже открывает
простое меню.

Установка и восстановление на Mac: скопировать каталог `plugins/menubar-status/macos`
на Mac и выполнить в нём `zsh install.sh` — он кладёт файлы в
`~/Library/Application Support/bb-menubar`, создаёт токен, ставит LaunchAgent
`dev.bb.menubar` (автозапуск, перезапуск при падении) и указывает SwiftBar папку
скрипта. SwiftBar ставится отдельно: `brew install --cask swiftbar`.

Для Claude Code на сервере установлен сторонний навык `ui-ux-pro-max`
(github.com/nextlevelbuilder/ui-ux-pro-max-skill) в `~/.claude/skills/ui-ux-pro-max`:
справочник правил UI/UX с локальным поиском, без сетевых вызовов. Восстановление:
клонировать репозиторий и скопировать `.claude/skills/ui-ux-pro-max` в `~/.claude/skills/`.

### Projects по последней активности тредов на любом уровне

В `machine-tabs` группы проектов сортируются по максимальному `updatedAt`
видимых неархивных тредов (при отсутствии — `createdAt`). На внешнем уровне
и внутри машины/даты учитываются треды соответствующей группы. Новая
активность поднимает проект; пустые проекты остаются внизу, равные даты
сохраняют исходный порядок. Сортировка самих тредов и машин/дат не меняется.

Адаптер штатного списка заменяет сохранённые позиции `project:<id>`
динамическим якорем `projects` только в отображаемых настройках Machine Tabs:
при чтении, ответе записи и realtime-обновлении. Это не сбрасывает хранимые
настройки BB; положение Pinned/Threads и остальные события сохраняются.
Обрабатываются оба уровня группировки. После обновлений BB нужно проверять
совместимость адаптера штатного списка.

Восстановление: `bb plugin build plugins/machine-tabs`, затем
`restore.py --plugins --apply`. Новых настроек нет. Проверка алгоритмов:
`node --experimental-strip-types --test plugins/machine-tabs/tests/project-order.test.mjs`,
проверка типов — `npx tsc --noEmit` в каталоге плагина.

### Проверка маршрута Claude и Voice Mode во время работы

`proxy-manager` каждые 5 секунд при открытом индикаторе проверяет процесс
Claude в фактической папке и на машине текущего треда. Linux использует
`/proc`, macOS — `ps`/`lsof`. Прямой маршрут/прокси подтверждается только
установленным TCP-соединением процесса с разрешённым IP Anthropic/прокси.
Неоднозначные процессы, собственные облачные шлюзы, отсутствие соединения
или доступа показываются как непроверенные. Нет процесса — отдельная подпись.
Статус Codex не используется для Claude. Доступность ответа API и системный
VPN/TUN эта проверка не подтверждает; подсказка описывает границы проверки.

Результат хранится только кратковременно в памяти. Настройки Claude, маршрут
и авторизация не меняются, запросы к модели не отправляются. В UI не
передаются переменные окружения, URL прокси с паролями или адреса соединений.
Тесты проверяют отсутствие ложного «Без прокси», неоднозначность и выбор
реальной машины треда; живой RPC проверен на Linux. macOS требует проверки
на устройстве, парсер покрыт тестом.

В патче Voice Mode убрано скрытие запуска при работающем агенте.
Замена штатной отправки по-прежнему допускается только в пустом поле
при неработающем агенте; кнопка остановки задачи остаётся доступной.
Патч остаётся в `plugins/voice-mode/changes.json` и сохраняется keeper.
Восстановление: собрать/установить `plugins/proxy-manager` штатным
`restore.py --plugins --apply`, для Voice Mode — сохранённый apply/keeper.

### Мобильная строка кнопок ввода

В `handoff-button` подпись Handoff скрывается до 767px, остаётся значок с
доступным названием. `proxy-manager` находит нижнюю строку также в тредах без
отдельных кнопок проекта/ветки/машины и переносит туда индикатор прокси,
чтобы он не занимал место рядом с голосом. `thread-account-usage` запрещает
перенос внутри штатной группы голосовых кнопок и отправки только на телефоне.
До 350px выбор модели получает собственную строку, чтобы не перекрывать кнопки.
Десктопные стили не меняются. Восстановление: собрать и установить эти три
локальных плагина через `restore.py --plugins --apply`. Проверять при обновлении
DOM-маркеров BB (`data-follow-up-composer-footer`, `data-promptbox-standard-actions`).
