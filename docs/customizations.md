# Настройка и восстановление

## Установка

План показывает `python3 scripts/restore.py --plugins`. Для применения запустите
его с `--apply` на машине сервера BB. Локальные плагины устанавливаются из
`plugins/<id>/`; сторонние — из сохранённых источников каталога.

`restore.py` читает `config/` и `.local/config/`. Локальные значения заменяют
одноимённые публичные ключи; вложенные словари и списки заменяются целиком.
Личные файлы плагинов обнаруживаются даже при отсутствии публичного файла.
Новый checkout без `.local/` получает только общие настройки.

## Сохранение

После изменения BB проверьте источник через `bb plugin list --json`, затем:

```sh
python3 scripts/snapshot.py --settings-only
python3 scripts/snapshot.py --check
python3 scripts/privacy_check.py
```

Снимок содержит список плагинов и настройки без секретных полей схемы.
Он сохраняется только в `.local/config/`. Полный режим без `--settings-only`
копирует исходники установленных локальных плагинов, поэтому требует чистого
каталога `plugins/` и отдельной проверки кода на личные значения.
Публичные настройки редактируются вручную после обезличивания.

`setup_tracking.py --apply` добавляет общее напоминание и включает Git-хук.
Хук проверяет актуальность приватного снимка и содержимое Git index.
Проверка истории перед публикацией: `python3 scripts/privacy_check.py --history`.
Коммиты, push и открытие доступа выполняются по отдельному поручению.

## Ручные шаги

Пароли и авторизации вводятся отдельно. Сетевой доступ Connect, маршруты прокси,
ACP-агенты и чувствительные состояния сетевых плагинов автоматически не меняются.
Идентификаторы машин после новой установки сопоставляются заново.
Сложные горячие клавиши, пользовательский CSS, выбранные вкладки и лимиты машин
проверяются вручную. Маршруты и аккаунты Claude не меняются при сборе снимка.

При установке Web BB Button задайте «Публичный адрес BB» (`webUrl`) в штатных
настройках плагина. Если на сервере уже задан `BB_APP_URL`, он может использоваться
при пустой настройке. Без корректного адреса плагин показывает статус «Требуется
настройка» и инструкцию; сохранение настроек повторяет его загрузку.
Переходов на главную по умолчанию нет. Личный URL хранится в BB и приватном
снимке `.local/config/plugins/web-bb-button.json`. Серверное перенаправление
`/api/v1/plugins/web-bb-button/http/open` открывает сохранённый адрес.
После правки плагина выполните `bb plugin build <путь>` и `bb plugin reload <id>`.

Личные адреса доставки бэкапа задаются в `.local/config/backup-delivery.json`:

```json
{
  "destinationHost": "host_example",
  "destinationDir": "/path/to/private/backups",
  "compatHost": "host_example"
}
```

`server_backup.py` также принимает `--destination-host`, `--destination-dir`,
`--recipient`. `apply_inbox_compat.py` принимает `--host` и без `--apply` только
проверяет известные контрольные суммы. При изменении upstream требуется новый
просмотр совместимости. Скрипты не читают и не меняют базу BB напрямую.

## Публикация изменений

Проверяйте diff и запускайте `scripts/privacy_check.py` для текущих файлов и с
`--history` для истории. Личные документы и конфигурацию храните в `.local/`.
При очистке уже существовавшей истории сохраните приватный Git bundle и свои
незакоммиченные файлы. Старые checkout нельзя сливать обратно в очищенную историю:
клонируйте репозиторий заново, затем перенесите собственные незавершённые правки.

Данные в `.local/` отсутствуют в GitHub. Шифрованное резервное копирование и
восстановление описаны в [server-backups.md](server-backups.md).

## Project Open

`plugins/project-open/` добавляет две иконки папки и терминала у проектов
и в заголовке треда. На компьютере они появляются при наведении/фокусе,
на touch видны без наведения. Стандартные список, меню и заголовок BB
сохраняются; иконки добавлены через React-порталы перед штатным Open.
Место зарезервировано постоянно: меняется только прозрачность, кнопки не
сдвигаются. Между исходными Open и переключателем панели нет скрытого блока.
Терминал запускается
штатными New tab → Start terminal. Папка вызывает исходный Open BB:
Finder/File Manager выбирается только если BB предоставляет такой пункт.
Для удалённых папок без поддержки Finder остаётся штатный выбор приложения.

Папка у проекта требует существующего треда в точном корне на выбранной
машине и может переключиться в него. Worktree не подставляется вместо корня.
Неоднозначные split-панели и отсутствие корневого треда дают объяснение.
Machine Tabs добавляет маркеры `data-machine-tabs-host-id` на существующие
контейнеры, чтобы кнопки различали одинаковые проекты на разных машинах.
DOM-привязки проверять после обновлений BB; подробности в README плагина.

Восстановление: `python3 scripts/restore.py --plugins --apply`. При ручной
установке выполнить `npm ci --include=dev` в каталоге плагина, затем
`bb plugin build plugins/project-open` и
`bb plugin install ./plugins/project-open --yes`. Также собрать и перезагрузить
Machine Tabs. Проверки — `npm test` и `npm run typecheck` в каталоге плагина.

Внешний Open → Terminal/VS Code требует отдельного SSH-сопоставления
на каждом клиентском устройстве. Используйте проверенный SSH-профиль:

```sh
bb-app client ssh-target set <server-origin> <ssh-profile> --host-id <host-id>
```

Если `bb-app` отсутствует в PATH на macOS, комплектный CLI доступен через
Electron в режиме Node (путь к установленному приложению уточнить):

```sh
ELECTRON_RUN_AS_NODE=1 /Applications/bb.app/Contents/MacOS/bb \
  /Applications/bb.app/Contents/Resources/app.asar/node_modules/bb-app/dist/bb-app.js \
  client ssh-target set <server-origin> <ssh-profile> --host-id <host-id>
```

Настройка сохраняется в клиентском `client.json`; приватный снимок сервера
её не применяет. Встроенный терминал BB не требует SSH-сопоставления.
Личные значения и инструкция восстановления конкретного клиента хранятся
в `.local/docs/project-open.md`; ключи и авторизации не копируются.

## Автоматизации и наблюдение за очередями

Исходники проверок сохранены в `scripts/thread_watchdog.py` и
`scripts/thread_queue_monitor.py`; резервное копирование — в
`scripts/server_backup.py`. Установленные автоматизации содержат отдельные
копии скриптов. Правка checkout сама по себе не меняет работающую проверку.

`scripts/automation_config.py --snapshot --project <project-id>` сохраняет
известные расписания этих скриптов в игнорируемый файл
`.local/config/automations.json`. Флаг `--project` можно повторять. В снимок
входят включённость, cron, часовой пояс, таймаут, рабочий каталог и только
разрешённые переменные окружения. Переписки, ключи, базы, содержимое бэкапов,
история запусков и наблюдений не сохраняются в репозитории. Приватный манифест
включается в зашифрованный архив `.local/config/`, описанный в
[server-backups.md](server-backups.md).

Восстановление: сначала `python3 scripts/automation_config.py` показывает
план без изменений; `python3 scripts/automation_config.py --apply` обновляет
существующие расписания или создаёт отсутствующие из исходников checkout.
Перед применением на новой установке сопоставьте project/thread ID, пути
и параметры доставки в приватном манифесте. Для другого хоста скрипты должны
быть доступны на хосте вызывающего CLI. Повторное применение сопоставляет
задания по ID, затем по точному имени. Неоднозначные имена останавливают импорт.

Проверки запускаются раз в минуту и не требуют модели. Общий монитор только
наблюдает очередь всех доступных проектов и посылает штатное BB-уведомление:
`turn-starting` дольше 5 минут, `thread-busy` дольше 15 минут либо исчерпанные
попытки доставки. Долгое ожидание не объявляется доказанным зависанием.
Запланированные сообщения, вопросы, ожидание плагинов и недоступные машины
не считаются таким сбоем. Уведомления ограничены одним на тред за 30 минут.
Обезличенные технические наблюдения (ID, время, статус, причина очереди)
хранятся только в служебной директории, с ротацией двух файлов до примерно
2 МБ каждый; состояния удаляются через 7 дней без наблюдений.

Отдельная защита одного выбранного треда повторяет доставку уже сохранённого
сообщения и возобновляет только явно диагностированный сбой запуска
`provider_turn_start_deadline` / `provider_turn_start_timeout`. Она не
останавливает работающий ход, не очищает контекст, не отвечает на вопросы,
не подтверждает разрешения и не возобновляет ручную остановку. Не более трёх
попыток до нового сообщения пользователя, с интервалом не менее 3 минут.
Новый запрос автоматически возвращает наблюдение без ручного включения.
Состояния и счётчики не содержат текста сообщений. Если проблема —
рассинхронизация BB при продолжающейся работе провайдера, принудительного
перезапуска нет: собираем данные для исправления причины.
