# v1.0.0 — первый стабильный выпуск и канал обновлений

Общий порядок — [docs/updates.md](../updates.md).

## Что изменилось

- Появился канал стабильных версий: релизы `vX.Y.Z` вместо отслеживания `main`.
- Новый плагин Config Updates сообщает о релизах и запускает их применение
  агентом по кнопке «Обновить с ИИ».
- Этот выпуск фиксирует текущие версии плагинов репозитория как исходную точку.
  Несовместимых изменений нет.

## Кому применять

- Всем, кто ставил плагины из этого репозитория из checkout
  (`bb plugin install path:…/plugins/<имя>`). Нужны BB 0.49+, Node.js 22+, npm.
- Обновляются только плагины, которые у вас уже установлены из этого checkout.
  Остальные шаги получают `not-applicable`; новые плагины этот выпуск не ставит.
- Кто ещё не поставил Config Updates, устанавливает его один раз вручную по
  [README плагина](../../plugins/config-updates/README.md); дальше обновления
  приходят через него.
- Не входят в выпуск: патчи к сторонним плагинам (`plugins/*-compat`,
  `plugins/voice-mode`), macOS-обработчики плагинов (`menubar-status/macos`,
  Project Open, Open on Mac) и личные настройки. Их установка описана в README
  соответствующих плагинов и не меняется этим выпуском.
- Все шаги выполняются на машине сервера BB; шагов для машин-исполнителей нет.

## Шаги

Все шаги однотипны и независимы друг от друга. ID шага: `plugin-<id плагина>`.

- `plugin-code-open` — Code Open (`plugins/code-open`)
- `plugin-config-updates` — Config Updates (`plugins/config-updates`)
- `plugin-file-local-open` — Open on Mac (`plugins/file-local-open`)
- `plugin-handoff-button` — Handoff Button (`plugins/handoff-button`)
- `plugin-machine-tabs` — Machine Tabs (`plugins/machine-tabs`)
- `plugin-menubar-status` — Menubar Status (`plugins/menubar-status`)
- `plugin-project-logo` — Project Logo (`plugins/project-logo`)
- `plugin-project-open` — Project Open (`plugins/project-open`)
- `plugin-proxy-manager` — Proxy Manager (`plugins/proxy-manager`)
- `plugin-push-button` — Push Button (`plugins/push-button`)
- `plugin-thread-account-usage` — Thread Account Usage (`plugins/thread-account-usage`)
- `plugin-voice-mode-keeper` — Plugin Keeper (`plugins/voice-mode-keeper`)
- `plugin-web-bb-button` — Web BB Button (`plugins/web-bb-button`)

Для каждого шага:

1. Где: сервер BB. Зависимостей нет.
2. Уже применён, если работающий плагин установлен из этого checkout, его версия
   равна `version` в `plugins/<id>/package.json` закреплённого коммита и статус
   `running` (отключённый пользователем плагин тоже считается). Неприменим, если
   плагин не установлен.
3. Применение: `npm ci --include=dev`, `bb plugin build`, `bb plugin reload <id>`
   в каталоге плагина — выполняет `python3 scripts/updates.py run v1.0.0/plugin-<id>`.
   Пути берутся из расположения checkout, вводить их не нужно.
4. Меняются `node_modules/` и `dist/` плагина и загруженная в BB версия.
   Настройки плагина и данные не затрагиваются.
5. Ожидаемый результат: `status: verified`, в `detail` — «<id> <версия> from this
   checkout».
6. Повтор безопасен: при совпадении версии шаг только проверяется.
7. Если плагин установлен из другого каталога или источника, шаг завершается
   ошибкой и ничего не заменяет: выясни у пользователя, какая установка нужна.
   При ошибке сборки прежняя загруженная версия продолжает работать; откат —
   вернуть каталог плагина к прежнему коммиту и пересобрать.

## Проверка релиза

- Установка автора (сервер BB на Linux, BB 0.49): все шаги проверены по
  фактическому состоянию и отмечены как уже применённые, без пересборки.
  Machine Tabs у автора работает из рабочей копии с ещё не опубликованными
  правками той же версии; в выпуск они не входят.
- Config Updates собран, установлен и проверен вживую: проверка релизов,
  карточка в боковой панели, запуск треда агента, отказ от второго запуска.
- Ветка «применить» (сборка и перезагрузка устаревшего плагина), пропущенные
  релизы, прерывание, машины-исполнители и параллельные запуски проверены
  автоматическими тестами `scripts/test_updates.py`, а не на чужой установке.
- Не проверялось: сервер BB на macOS и Windows, установка другого пользователя.
