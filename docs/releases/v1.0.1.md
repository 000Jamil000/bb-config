# v1.0.1 — понятная карточка обновлений и автоархив треда

Общий порядок — [docs/updates.md](../updates.md).

## Что изменилось

- Карточка Config Updates в боковой панели и раздел настроек теперь прямо
  показывают: какая версия установлена и с какого числа, какая доступна и когда
  опубликована, когда была последняя проверка и идёт ли обновление сейчас.
- Кнопка называет версию: «Обновить до vX.Y.Z с ИИ».
- Название релиза больше не повторяет номер версии.
- Тред обновления сам уходит в архив, когда релиз применён полностью и агент
  закончил ответ. При остатке или ошибке тред остаётся. Отключается настройкой
  плагина «Архивировать тред после успешного обновления».
- Несовместимых изменений нет.

## Кому применять

- Тем, у кого установлен Config Updates из checkout этого репозитория. Если
  плагин не установлен, шаг неприменим.
- Требования прежние: BB 0.49+, Node.js 22+, npm. Только сервер BB.

## Шаги

### `plugin-config-updates`

1. Где: сервер BB. Зависимостей нет.
2. Уже применён, если работающий Config Updates установлен из этого checkout,
   имеет версию 0.1.2 и статус `running`. Неприменим, если плагин не установлен.
3. Применение: `python3 scripts/updates.py run v1.0.1/plugin-config-updates`
   (`npm ci --include=dev`, `bb plugin build`, `bb plugin reload config-updates`).
4. Меняются `node_modules/`, `dist/` плагина и загруженная версия. Настройка
   `repository`, журнал и сохранённый результат проверки сохраняются.
5. Ожидаемый результат: `status: verified`, в `detail` —
   «config-updates 0.1.2 from this checkout». После перезагрузки страницы BB
   карточка показывает строки «Установлено», «Доступно», «Проверено».
6. Повтор безопасен. Плагин перезагружается во время обновления, которое сам
   запустил: тред агента при этом продолжает работу, журнал не затрагивается.
7. При ошибке сборки продолжает работать прежняя версия; откат — вернуть каталог
   плагина к `v1.0.0` и пересобрать.

## Проверка релиза

- Установка автора (сервер BB на Linux, BB 0.49): шаг применён командой
  `run` — плагин пересобран и перезагружен на 0.1.2, результат подтверждён
  проверкой версии; карточка проверена в браузере.
- Автоархив проверен автоматическим тестом плагина; на живом обновлении он
  впервые сработает при применении этого релиза.
- До этого на той же установке полностью пройдено обновление до `v1.0.0`
  через кнопку «Обновить с ИИ».
- Не проверялось: сервер BB на macOS и Windows, установка другого пользователя.

## Контекстные иконки: `plugin-project-logo`
- Project Logo 0.2.0 создаёт оригинальный SVG по названию проекта и первому
  сообщению, если подходящей готовой картинки нет. Иконка общая для проекта и
  его чатов. Существующие изображения сохраняются.
- Где: сервер BB, зависимостей от других шагов нет. Требования: BB 0.49+,
  Node.js 22+, npm; для отображения нужен Machine Tabs.
- Проверка: плагин из текущего checkout, версия 0.2.0, статус running (либо
  сохранённое пользовательское отключение). Если не установлен — неприменим.
- Применение: `python3 scripts/updates.py run v1.0.1/plugin-project-logo`.
  Скрипт проверяет версию, выполняет npm ci, сборку, reload и повторную проверку.
- Ожидается `verified`, detail: `project-logo 0.2.0 from this checkout`.
  Новые сессии получают инструкцию создавать контекстный SVG. Старые отметки
  checked без версии больше не блокируют попытку; отсутствующий значок не
  считается завершением. Уже работающие сессии получают правила после штатного
  перезапуска runtime по окончании хода; история сохраняется.
- Повтор безопасен; существующий значок не меняется. При недоступном источнике
  агент сообщает ограничение и продолжает работу, следующий запуск может повторить.
- Откат: восстановить plugins/project-logo из v1.0.0, npm ci --include=dev,
  bb plugin build plugins/project-logo, bb plugin reload project-logo.
  Созданные иконки хранятся в самих проектах; откат плагина их не удаляет.
