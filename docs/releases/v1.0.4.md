# v1.0.4 — Voice Mode: личный форк и штатные обновления

Общий порядок — [docs/updates.md](../updates.md).

## Что изменилось

- Voice Mode использует стабильные релизы личного форка и штатные обновления BB.
- Голос кратко сообщает подтверждённый этап, не путая ожидание с отсутствием контекста.
- Keeper не накладывает правки повторно на форк и продолжает защищать остальные плагины.
- Перенос сохраняет несекретные настройки; при настроенном секрете Voice Mode
  останавливается до удаления. Такие установки требуют отдельного переноса секрета.

## Шаги

### `plugin-voice-mode-keeper` — Plugin Keeper 0.2.3: штатные обновления форка Voice Mode

Keeper 0.2.3 пропускает патчинг форка Voice Mode, установленного через диапазон
стабильных релизов. Новые совместимые версии не блокируются фиксированными хешами.
Правки остальных плагинов остаются под защитой. Шаг voice-mode-personal-fork
отдельно выполняет разовую смену источника; версия Keeper не доказывает её успех.

### `voice-mode-personal-fork` — Voice Mode: стабильные релизы форка через BB

Voice Mode переходит с каталога или первоначального фиксированного коммита
на стабильные релизы форка `@^0.2.0`. Затем обновления 0.2.x приходят через штатную
проверку плагинов BB и применяются командой `bb plugin update voice-mode`.
Отдельный релиз bb-config для каждой версии Voice Mode не требуется.

Разовая миграция сохраняет несекретные настройки и состояние включения, но
отказывается от удаления при наличии секрета Voice Mode. Подключающий плагин и
его авторизация не меняются. Голосовой сеанс нужно включить заново. --check
сверяет канал установки и совместимую стабильную версию, не фиксированные хеши.
Приватный журнал содержит прежний источник и настройки для восстановления.

### `voice-waiting-context` — Voice Mode: корректное ожидание контекста треда

Голос после передачи запроса подтверждает проверку и ждёт результат треда.
Ожидание больше не описывается как отсутствие контекста. Проверка активной работы
не передаёт устаревший ответ от предыдущей задачи. Завершённые ответы и ожидание
подтверждения пользователя обрабатываются отдельно.

Для форка шаг проверяет штатный канал стабильных релизов. Каталоговый резервный
путь использует keeper с тестами, проверкой типов и сборкой до активации. Перезагрузка завершает текущую
голосовую сессию — после обновления её нужно включить снова. Проверка установки:
`python3 plugins/voice-mode/apply.py --check`. Живая приёмка: спросить о контексте,
затем «ещё работаешь?»; голос ждёт ответ и не утверждает, что контекст отсутствует.
Новых настроек, отдельной памяти и элементов интерфейса нет.

## Проверка релиза

- Валидация манифеста и все Python-тесты scripts из чистого клона коммита релиза.
- Тесты Voice Mode Keeper/патчера, TypeScript и сборка keeper.
- Voice Mode v0.2.0: 53 теста, TypeScript и сборка при публикации форка.
- Проверка приватности истории Git; сопоставление изменений с тремя шагами релиза.
- После публикации: проверка фактической установки через fetch/begin/run/finish.
- Живое голосовое поведение зависит от модели; backend-тесты не заменяют такую проверку.
