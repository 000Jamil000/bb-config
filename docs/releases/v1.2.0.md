# v1.2.0 — Фильтры Machine Tabs, выбор вида KodaForge, поддержка Windows и маршруты моделей

Общий порядок — [docs/updates.md](../updates.md).

## Что изменилось

- Machine Tabs 0.2.0: кнопка-воронка в строке поиска открывает фильтры по теме и проекту со счётчиком «показано из всего». Значок перед названием треда выбирается: значок проекта (как раньше) или значок темы; при первой загрузке списка плагин спрашивает, какой оставить.
- Project Open 0.3.0: папку и терминал треда можно перенести из строки в меню «…» настройкой `placement`. По умолчанию кнопки остаются в строке.
- KodaForge Inspector 0.3.0 — новый плагин, ставится по выбору: чат по центру редактора KodaForge и автооткрытие одного выбранного диалога. Вид выбирается в окне с примерами при первом открытии редактора в проекте; без выбора вид штатный.
- Поддержка Windows: скрипты репозитория, Config Updates 0.1.5 и Plugin Keeper 0.2.4 работают на сервере BB под Windows; Open on Desktop 0.2.0 (прежний Open on Mac) открывает файлы и на Windows-компьютере; Menubar Status 0.3.1 получил клиент для панели задач Windows; Browser Page 0.1.0 — навык для машин без Browser Automation, ставится по выбору.
- Proxy Manager 0.3.2: на странице «Подключения» для каждой машины можно выбрать маршрут моделей Codex и Claude Code только внутри BB: напрямую, через OpenCodex или как в CLI. Пока выбор не сделан, поведение агентов не меняется.
- Config Updates больше не печатает «Новых стабильных релизов нет» рядом с ошибкой проверки.
- Project Catalog 0.3: группы категорий, несколько категорий у проекта, треды и быстрые действия в карточке.

Известные ограничения этой версии: после доработки Windows-часть на Windows не запускалась, а маршруты моделей Proxy Manager не проверялись на машине с работающим OpenCodex — оба изменения проверены тестами на Linux. Клиент Menubar Status для Windows не проверяет, что порт панели занят его собственным помощником. Путь файла из треда на Windows при сервере BB на Linux разрешается по правилам сервера.

## Шаги

### `config-updates-failed-check` — Config Updates 0.1.4 корректно сообщает об ошибке повторной проверки

На сервере с установленным Config Updates шаг обновляет плагин до версии этого релиза (исправление появилось в 0.1.4).
После успешной проверки без новых релизов последующая ошибка в командах
`check` и `status` выводит причину и возвращает код 1. При потере checkout
сообщение подсказывает, как привязать плагин к постоянной рабочей копии.

Проверка шага сверяет версию, источник и состояние плагина. Регрессионный
тест в `plugins/config-updates` проверяет обе команды при сбое. Для отката
повторите установку плагина из предыдущего стабильного релиза.

### `plugin-browser-page` — Browser Page 0.1.0: страницы встроенного браузера для агентов на Windows

Выполняется на сервере BB. Зависимостей нет. Новый компонент: ставится только с согласия
пользователя (`run … --install`).

Плагин-навык для машин, где Browser Automation не запускается (на Windows у DevBrowser нет
сборки): скрипт `bb-page.mjs` штатными командами `bb browser` получает вкладку встроенного
браузера и даёт агенту переход, текст страницы, список и нажатие элементов, ввод и снимок.
На установках только с Linux и macOS он не нужен: записать `not-applicable`.

Уже применено, если установлен `browser-page` 0.1.0 из этого checkout. Данных и настроек у
плагина нет.
Проверка в треде на машине с окном BB:
`node plugins/browser-page/skills/browser-page/bb-page.mjs open https://example.com`, затем
`… text` и `… close`. Повтор безопасен. Откат: `bb plugin uninstall browser-page`.

### `plugin-config-updates-windows` — Config Updates 0.1.5: работа на сервере BB под Windows

Выполняется на сервере BB. Зависимостей нет.

Плагин и `scripts/updates.py` теперь работают и на Windows: интерпретатор Python задаётся
настройкой `pythonPath`, скрипты запускаются в режиме UTF-8 без окна консоли, checkout
сопоставляется с источником проекта без учёта регистра и вида слэшей. На Linux и macOS
поведение прежнее.

Уже применено, если установлен `config-updates` 0.1.5 из этого checkout. Шаг пересобирает и

На Windows после шага, если `python` в PATH сервера — заглушка Microsoft Store, задайте
`bb plugin config config-updates set pythonPath <полный путь к python.exe>`.
Проверка: `bb config-updates check` завершается кодом 0 и печатает установленную версию.
Повтор безопасен. Откат — по полю `rollback`.

### `plugin-kodaforge-inspector` — Центральный чат KodaForge и инспектор совместимости

На сервере BB с установленным KodaForge можно добавить центральный чат для рабочих пространств диалогов. При первом применении шаг установки инспектора требует согласия пользователя.

1. Установите инспектор шагом релиза с флагом `--install`. Для отдельной установки из checkout используйте [инструкцию плагина](../../../plugins/kodaforge-inspector/README.md).
2. Обновите страницу BB. Откройте обычный диалог, затем вручную перейдите в KodaForge. Появится окно выбора вида со схемами; заранее отмечен штатный, и до выбора ничего не меняется. Выберите «Чат по центру», нажмите «Применить» (для этого проекта) или «Сохранить для всех» и проверьте обе центральные вкладки, открытие файла, ветку Git и терминал.
3. Выполните `bb kodaforge-inspector status`. Поле `browser` содержит итог и время последней проверки.
4. Для возврата к штатному виду нажмите «Вид…» и выберите его, либо выполните `bb plugin config kodaforge-inspector set layout native`.

### `plugin-proxy-manager-gateway-availability` — Proxy Manager 0.3.1: проверка доступности OpenCodex

# Проверка доступности OpenCodex

Шаг выполняется на сервере после `next/plugin-proxy-manager-model-routes`, если
Proxy Manager установлен. Стандартный local-plugin шаг собирает и перезагружает
версию из закреплённого коммита, затем проверяет установленный источник и версию.
Host worker обновляется при следующем вызове. Пропустить при отсутствии плагина.
Ожидается версия 0.3.2 или содержимое закреплённого более нового коммита.

Проверить в Подключениях: у машины без настройки OpenCodex пункт виден, но отключён,
с пояснением «OpenCodex не настроен»; прямой режим доступен. Проверка повторяется
по кнопке и перед сохранением. У настроенного шлюза отображается его доступность.
Не менять режим пользователя ради проверки. KV, исходные профили и VPN сохраняются;
новых личных настроек шаг не добавляет. Повторить шаг после прерывания безопасно.
Для отката вернуть прежнюю версию плагина и build/reload; прежняя версия не защищает
от выбора недоступного шлюза.


## Проверка OpenCodex (0.3.1)

Прямой маршрут доступен независимо от OpenCodex. Для каждого провайдера на каждой
машине пункт «Через OpenCodex» остаётся видимым, но недоступен до успешной проверки.
Показываются состояния: пока не проверен, не настроен, настроен, но не запущен или
недоступен, доступен; для отключённой машины — «Машина офлайн».

Host читает `$OPENCODEX_HOME/config.json` (по умолчанию `~/.opencodex/config.json`):
нужны явный `port` и запись `providers.openai` для Codex либо `providers.anthropic`
для Claude. Отключённая запись не считается настройкой. Для Codex обычный профиль
также должен указывать на этот порт через localhost/127.0.0.1 и `/v1`. Затем
read-only запрос `/healthz` должен вернуть `service: opencodex`, `status: ok`.
Другой локальный прокси не считается OpenCodex. Поддерживается локальный HTTP-шлюз;
неизвестные схемы конфигурации считаются ненастроенными. Проверка не запускает шлюз,
не читает токены, не вызывает модели и не меняет исходные настройки.

Таймаут — 1,5 секунды, кэш — 30 секунд. «Проверить OpenCodex» обновляет состояние;
сохранение opencodex всегда выполняет новую host-проверку, прежде чем менять KV.
Подготовка runtime использует кэш. Claude получает адрес с портом из конфигурации,
без фиксированного 10100. Доступность шлюза не гарантирует права аккаунта на модели.
Режим direct и системный VPN автоматически не переключаются.

Установка/восстановление: `bb plugin build plugins/proxy-manager`, затем
`bb plugin reload proxy-manager`; выбранные режимы сохраняются. При откате вернуть
исходники предыдущей версии и повторить build/reload; старый выпуск не проверял шлюз.
Проверки: TypeScript, тесты отсутствующей настройки, остановленного и чужого сервиса,
нестандартного порта, независимости direct, кэша и повторной серверной проверки.

### `plugin-proxy-manager-model-routes` — Proxy Manager 0.3.0: отдельный маршрут моделей BB

# Отдельный маршрут моделей BB


## Маршрут моделей только в BB (0.3.0)

В «Подключения → Маршрут моделей BB» для Codex и Claude Code на каждой машине
можно выбрать «Напрямую» или «Через OpenCodex». Этот выбор не изменяет системный
VPN, HTTP_PROXY/HTTPS_PROXY, обычные файлы конфигурации и внешние процессы CLI.
Это отдельный механизм от старого выбора сетевого прокси ниже на странице.
Модели доступны в пределах авторизации выбранного провайдера; маршрутизатор не
предоставляет доступ к моделям другого провайдера.

Команды: `bb proxy-manager model-route` (список) и
`bb proxy-manager model-route <host-id> <codex|claude-code> <direct|opencodex|inherit>`.

Режим `inherit` («Как в CLI») удаляет выбор: BB перестаёт подставлять маршрут и
агент работает с собственными настройками CLI. Если тред не удалось остановить
при смене маршрута, выбор всё равно сохраняется, а тред перезапускается после
завершения ответа. Сообщение, задержанное из-за недоступной машины или шлюза,
повторяется автоматически через 30 секунд.
До первого выбора настройки провайдера не переопределяются.
Idle-процессы выбранного провайдера BB освобождаются; активные ответы сначала
завершаются. Список моделей может оставаться кэшированным до обновления BB.

Для Codex прямой режим использует CODEX_HOME в приватном host-data плагина.
Config берётся из обычного профиля, но локальный endpoint и каталог OpenCodex
заменяются штатным OpenAI-маршрутом. Авторизация общая с обычным профилем: `auth.json` профиля BB —
ссылка на обычный файл, а где ссылку создать нельзя или CLI заменил её своим
файлом, при следующей подготовке более свежий файл переносится на обе стороны.
Файлы `.env` (сетевые настройки прокси), `hooks.json` и `AGENTS.md` повторяют
обычный профиль, включая удаление. История, skills, plugins, rules и
вложения доступны через ссылки на обычные каталоги. Базы индексов и кэши нового
профиля отдельные. MCP с привязкой авторизации к CODEX_HOME может потребовать
повторного входа. Возврат через OpenCodex выбирает исходный CODEX_HOME.
Для Claude меняется только ANTHROPIC_BASE_URL процесса BB; авторизация остаётся
штатной. Адрес OpenCodex для Claude: http://127.0.0.1:10100.

Выбор маршрута не доказывает доступность API. Внешние custom endpoints,
проектные переопределения и особые способы авторизации требуют отдельной проверки.
При ошибке подготовки отправка сообщения задерживается; история не очищается.
Публичные RPC возвращают лишь режим, путь профиля и описание; токены не возвращаются.

## Проверка релиза

Проверьте манифест через `python3 scripts/updates.py validate v1.2.0`. Тесты репозитория запускаются командой `python3 -m unittest discover -s scripts -p 'test_*.py'`, тесты каждого плагина — командой `npm test` в его каталоге после `npm ci --include=dev`.

Перед публикацией на Linux прошли: тесты скриптов, тесты и проверка типов Config Updates, Machine Tabs, Project Open, KodaForge Inspector, Proxy Manager, Open on Desktop и Menubar Status, тесты Plugin Keeper и Voice Mode, проверка приватности истории. Project Open и фильтры Machine Tabs дополнительно проверены в работающем BB.
