# Зашифрованные резервные копии

## Личная конфигурация

`python3 scripts/private_backup.py` упаковывает `.local/config/` и `.local/docs/`
и шифрует архив через age. Получатель берётся из
`.local/config/backup-encryption.json` (`recipient`) либо `BB_BACKUP_RECIPIENT`.
Без получателя скрипт отказывается создавать архив. Закрытый ключ не требуется
для шифрования и никогда не хранится в Git. Выходной файл имеет права 0600.

Архив появляется в `.local/backups/config/`. Обязательно скопируйте его на другую
машину или внешний носитель; локальная копия не защищает от потери сервера.
Старую историю `.local/privacy-migration/` скрипт намеренно не включает.

Восстановление: расшифруйте архив на доверенной машине командой
`age --decrypt -i /private/path/identity.txt -o /private/path/config.tar.gz archive.age`,
просмотрите `tar -tzf /private/path/config.tar.gz`, затем распакуйте его в корень
checkout. Архив содержит только `.local/config/` и `.local/docs/`.
Не публикуйте расшифрованный архив и удалите его после восстановления.
После возвращения личных файлов запустите `python3 scripts/restore.py` и проверьте
план, затем примените его с `--plugins --apply` на машине сервера.

## Экспорт BB

`scripts/server_backup.py` использует штатный экспорт BB, проверяет manifest,
шифрует архив и доставляет его через BB на указанную машину. Параметры доставки
хранятся в `.local/config/backup-delivery.json` или передаются флагами.
Получатель — `.local/config/backup-encryption.json` или `BB_BACKUP_RECIPIENT`.
Восстановление ключа на macOS поддерживает `scripts/backup_keys.py` через Keychain.
Ключ нельзя передавать в чат, Git или аргументы shell.

Архив экспорта BB не включает рабочие каталоги проектов и `.local/config/` этого
репозитория. Для них необходим отдельный зашифрованный архив, описанный выше.
Сохранённые в BB автоматизации содержат собственные копии скриптов: изменение
checkout не обновляет их автоматически. Существующее расписание при разделении
репозитория не изменяется. При обновлении автоматизации задайте явные параметры
доставки и получателя, доступные в её окружении выполнения.

После потери сервера используйте штатный `bb server import` в новую пустую
директорию совместимой версии BB. Не редактируйте базу вручную. Прежний сервер
должен быть остановлен до запуска восстановленной копии. Учётные данные CLI и
рабочие проекты восстанавливаются отдельно. Перенос живого сервера требует
отдельного явного поручения.
