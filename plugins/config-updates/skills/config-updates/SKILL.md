# Config Updates

Сообщает о новых стабильных релизах репозитория доработок BB и запускает их
применение агентом. Сам плагин ничего не устанавливает.

## Команды

```sh
bb config-updates status [--json]   # последний результат, без сети
bb config-updates check [--json]    # проверить GitHub сейчас
bb config-updates start             # создать тред агента для обновления
```

Код выхода 1 у `status`/`check` означает **ошибку проверки** (сеть, лимит
GitHub, нет журнала). Не сообщай при этом, что обновлений нет.

Интерфейс: значок «Обновления доработок BB» в нижнем ряду боковой панели
раскрывает карточку с версией, описанием и кнопкой «Обновить с ИИ»; при новом
релизе карточка открывается сама (не чаще раза в сутки на версию). Полное
описание — раздел «Обновления доработок» в настройках плагина. Проверка по
расписанию — каждые шесть часов.

## Как это устроено

- Учитываются только опубликованные релизы `vX.Y.Z`; draft, prerelease и
  коммиты `main` не считаются.
- Установленная версия берётся из журнала `scripts/updates.py status`, а не из
  checkout или тега.
- `start` закрепляет тег и SHA, находит проект BB с этим checkout на машине
  сервера и создаёт в нём тред. Существующий тред обновления или открытый
  запуск переиспользуются: второго параллельного обновления не будет.
- Плагин должен быть установлен из checkout (`path:…/plugins/config-updates`):
  он ищет рядом `scripts/updates.py`. Настройка `repository` (owner/repo) нужна
  только если `origin` checkout не ведёт на GitHub.

## Применение обновления

Порядок обязателен и описан в `docs/updates.md` закреплённого коммита:
`fetch` → чтение `docs/releases/<версия>.md` → `begin` → `run`/`record` по шагам
→ `finish` → `bb config-updates check`. Не применяй `scripts/restore.py`, не
используй `main`, не помечай шаг выполненным без проверки.

## Диагностика

- «Версия не определена» — журнала нет. Это допустимо: каждый шаг проверяется
  по фактическому состоянию. Для установки сразу из релиза — `baseline`.
- «Добавьте каталог … как проект BB» — checkout не подключён к BB как проект.
- «Another update run is open» — см. `python3 scripts/updates.py status`,
  проверь тред-владельца; `begin … --takeover` только если он точно остановлен.
- Остаток после частичного применения виден в `status` (`partial.remaining`).
